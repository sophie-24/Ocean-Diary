## 1. 처리 목적과 항목

| 목적 | 처리 항목 | 처리 근거 확정 |
|---|---|---|
| 이메일 로그인과 계정 유지 | Supabase 사용자 ID, 이메일 주소, 인증 세션 토큰(Android Keystore/iOS Keychain 기반 기기 보호 저장소) | [서비스 계약 이행/동의 등 적용 근거와 법 조항 검토 후 기재] |
| 사진 속 생물 식별과 개인 도감 제공 | 사용자가 선택한 해양 사진, 업로드 형식·크기·해시, 식별 작업·후보·결과, 사용자가 확인한 종 | [목적별 근거와 필수·선택 항목 확정] |
| 발견 기록 제공 | 종 선택 여부와 방식, 관찰 일시, 사용자가 선택적으로 입력한 넓은 지역명 | [목적별 근거 확정] |
| 서비스 보안과 요청 제한 | API 요청 식별자, 호출 시각, 요청 종류, 호출 제한 판단용 해시 버킷 값 | [보안 목적 근거, 구체 보유 기간 및 운영 로그 항목 확정] |

GPS 좌표와 사진 EXIF 위치정보를 수집해 저장하지 않는다. 서버는 사진을 다시 인코딩하며 EXIF를 제거한다. 다이버가 직접 입력하는 지역명은 선택 사항이며 발견 기록에 포함된다. 계정 데이터는 공개되지 않는 개인 데이터다.

앱은 중단된 발견 작성 흐름을 이어가기 위해 선택 사진의 임시 사본을 앱 cache에 둔다. cache는 저장 공간 확보를 위해 운영체제가 비울 수 있으므로 앱을 다시 열었을 때 사진 초안이 사라져 있을 수 있다. 저장 완료·작성 취소·로그아웃 때 앱이 사본을 삭제하고, 앱 시작 시 현재 초안이 참조하지 않는 앱 전용 임시 사진을 정리한다. cache 경로를 사용해도 실제 Android/iOS 백업 포함 여부는 단말과 설정에서 출시 전에 확인한다. [Expo Filesystem 경로 안내](https://docs.expo.dev/versions/v58.0.0/sdk/filesystem/), [Android Auto Backup](https://developer.android.com/identity/data/autobackup), [Apple 파일시스템 사용 안내](https://developer.apple.com/documentation/foundation/using-the-file-system-effectively)

로그인 세션 토큰은 일반 앱 설정과 분리된 Android Keystore/iOS Keychain 기반 보호 저장소에 두며, Android 백업에서 SecureStore 항목을 제외하도록 앱 설정을 구성한다. 보호 저장소가 복원되지 않거나 읽을 수 없는 경우 다시 로그인해야 할 수 있다. 단말 백업·복원과 재로그인 동작은 출시 전 실제 기기에서 확인한다.

## 2. 사진·AI 처리

기본 설정은 `mock` provider이며 외부 AI로 사진을 전송하지 않는다. 운영자가 외부 provider를 켜는 경우 사용자는 업로드 전에 provider와 안내 버전을 확인하고 명시적으로 동의해야 한다. 동의한 경우에도 동의 정보가 현재 서버 설정과 일치하지 않으면 서버는 사진을 외부로 보내지 않는다.

현재 OpenAI 연동 코드는 사진과 종 카탈로그 문맥을 Responses API에 보내고 `store: false`를 지정한다. 사용자 ID, 이메일, 관찰 일시와 지역명은 이 요청 본문에 포함하지 않는다. OpenAI는 API 입력·출력을 기본적으로 모델 학습에 사용하지 않는다고 안내하지만, abuse monitoring 로그에는 콘텐츠가 포함될 수 있고 기본 보유기간은 최대 30일이며 법률·안전 예외가 있을 수 있다. 실제 계정의 데이터 제어 설정, 선택 모델·기능, 처리 지역은 출시 전에 확인해 아래 수탁·국외 이전 표와 사용자 동의 화면에 반영한다. [OpenAI 데이터 제어 안내](https://developers.openai.com/api/docs/guides/your-data)

AI 결과는 종 식별 후보이며 정답이나 확정 판정이 아니다. 사용자가 후보를 직접 확인하거나 다른 종을 선택해야 발견 기록에 저장된다. 모델의 질적 신뢰 라벨은 보정된 확률이 아니다.

## 3. 보유 및 파기

| 데이터 | 기본 보유 기준 | 파기 방식 |
|---|---|---|
| 미저장 원본 업로드 | 업로드 주소 만료 후 정리 worker가 15분 유예를 두고 삭제 시도. 정상 완료 때는 정제 처리 후 원본 객체를 즉시 삭제 시도 | 객체 스토리지에서 삭제하고 실패하면 worker가 재시도. worker 중단·스토리지 장애 시 실제 삭제는 지연될 수 있음 |
| 발견 기록에 연결되지 않은 처리 사진 | 생성 후 7일이 지나면 worker가 정리 | 객체 삭제 후 미디어 row를 삭제 처리. 실제 서비스에서는 정리 worker 가동 상태를 운영 점검 |
| 저장된 발견 사진 및 활성 발견 기록 | 사용자가 발견을 삭제하거나 계정을 삭제할 때까지 | 마지막 활성 발견이 삭제되면 사진 객체를 비동기로 삭제 요청하고 실패 시 재시도 |
| 사용자가 삭제한 발견 정보 | 앱에서 즉시 숨김. 기본 30일(`DELETED_OBSERVATION_RETENTION_DAYS`) 보관 뒤 worker가 DB에서 영구 삭제 | 관련 객체가 실제 삭제되었고 다른 기록 참조가 없을 때 미디어 row도 정리. worker 중단 시 기한이 늘어날 수 있음 |
| 계정 삭제 후 차단 tombstone | 기존 access token이 모두 만료될 수 있도록 설정된 최대 JWT 수명까지. 기본값 24시간 | worker가 만료 후 tombstone을 삭제. 계정의 사진·발견·식별 자료 및 Supabase Auth 계정 삭제를 먼저 요청 |
| API/호스팅·인증·스토리지 운영 로그 및 백업 | [실제 각 사업자, 로그 유형, 백업 주기·파기 기한 확인 후 기재] | [실제 계약·운영 설정을 확인해 기재] |

법령상 별도 보존 의무가 적용되는 항목이 있다면 해당 법적 근거, 항목과 기간을 확정해 별도 표기한다. 현재 MVP는 worker 기반 정리를 사용하므로 worker가 장기간 중단되거나 외부 스토리지 오류가 지속되면 코드상 목표 기한보다 실제 파기가 늦어질 수 있다.

## 4. 처리 위탁·제3자 제공·국외 이전

공개 전 운영 설정을 확인해 실제 사업자명, 위탁 업무, 저장·처리 국가, 이전 항목·시점·방법, 근거, 보유기간과 연락처를 기재한다. 아래 표의 제공자 유형만으로 공개해서는 안 된다.

| 수탁자/제공받는 자 | 업무 | 이전되는 데이터 | 국가/이전 경로 | 보유·파기 |
|---|---|---|---|---|
| Supabase — [실제 프로젝트 사업자/리전 확인] | 이메일 인증, 사용자 ID·세션 관리, [실제 배포 시 DB/호스팅 사용 여부 확인] | 이메일, 사용자 ID, 인증 관련 데이터 | [프로젝트 리전과 국외 이전 여부 확인] | [계약 및 설정 확인] |
| S3 호환 객체 스토리지 — [실제 운영 사업자 확인; 개발은 로컬 MinIO] | 사진 객체 저장·서명 URL 발급 | 사진, 객체 키 및 처리 메타데이터 | [실제 리전/이전 여부 확인] | 위 3절의 삭제 일정 및 제공자 백업 정책 확인 |
| API/DB 호스팅 — [실제 운영 사업자 확인] | API·PostgreSQL 운영, 보안 및 진단 로그 | 계정 연결 ID, 발견·식별 데이터, 운영 로그 | [실제 리전/이전 여부 확인] | [실제 로그·백업 보유기간 확인] |
| OpenAI API — 사용자가 동의한 OpenAI provider 설정 때만 | 사진 속 종 후보 생성 | 사진 이미지와 종 카탈로그 문맥 | [계약·프로젝트 설정의 처리 지역 확인] | OpenAI API 데이터 제어와 계정 설정을 검토해 기재 |

현재 개발용 `.env.example`은 Supabase URL과 실제 S3/호스팅 사업자를 확정하지 않는다. 로컬 MinIO 주소와 기본 자격증명은 개발에만 사용한다. 운영 provider를 확정하기 전에는 이 표를 완성할 수 없다.

## 5. 정보주체의 권리와 행사 방법

사용자는 법령이 정한 범위에서 개인정보 열람, 정정, 삭제, 처리정지 등 권리를 행사할 수 있다. 앱은 발견 수정·삭제와 계정 삭제 요청 기능을 제공한다. 이메일·계정정보 정정, 열람·처리정지 등은 [개인정보 문의 이메일/전화번호]로 요청한다. 대리인 요청과 본인 확인 방법, 요청 처리 기한, 이의 제기 및 분쟁 조정 절차는 운영자 검토 후 구체화한다.

앱의 AI 후보는 사용자에게 제안만 하며 자동으로 발견 종을 확정하거나 법적·중대한 효과를 만드는 결정을 하지 않는다. 사용자는 후보를 선택하지 않고 직접 검색하거나 미확인으로 저장할 수 있다.

## 6. 안전성 확보 및 자동 수집

현재 구현에는 사용자 소유권 확인, 개발/운영 인증 경계, 요청 제한, 비공개 presigned 사진 URL, EXIF 제거, signed upload key와 처리 이미지 key 분리가 포함된다. 이는 시스템 설계 사실이며, 운영 환경에서 암호화·접근권한·키 관리·백업·침해사고 대응이 실제 설정됐다는 보증은 아니다. 실제 운영 설정과 개인정보 보호법상 안전성 확보조치를 확인해 공개 문구를 확정한다.

앱 코드는 광고 쿠키나 위치 SDK를 사용하지 않는다. 운영 빌드에서 분석·크래시 리포팅·플랫폼 진단 SDK가 추가되는지 확인하고, 해당하는 자동 수집 장치와 거부 방법을 이 절에 반영한다. 서버/호스팅 access log의 IP·경로·보유기간도 운영자와 제공자 설정을 확인해 공개한다.

## 7. 변경 및 공개

최종 방침은 앱의 계정/개인정보 설정과 로그인 영역에서 쉽게 찾을 수 있도록 공개한다. 처리 목적, 항목, 수탁자, AI provider, 이전 국가 또는 보유 기간 변경 시 변경 내용을 확인할 수 있는 방법과 시행일을 안내한다.
